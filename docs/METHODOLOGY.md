# Research methodology
**Data.** `program_gen.py` renders one random abstract program (functions, declarations, if/else, for, while, calls, prints, comments, blank lines, K&R/Allman, 2/4-space indent) as C, C++, Java or Python. Each is compiled by the real toolchain first (0 of 600 rejected). 150 programs/language.
**Corruptions.** 10 kinds (missing `;` `)` `}` `,` `:`, stray token, doubled operator, dangling operand, malformed declaration, Python indentation), single-line, line numbering preserved; the edited line is ground truth. A variant is kept only if the real compiler rejects it with a syntax error (3,439 of 3,600). A deleted `}` leaves an empty line indistinguishable from ordinary blank lines.
**Split.** By original program (hash of id): 420 / 95 / 85 programs = 2,403 / 547 / 489 samples; a test asserts no program is in two splits.
**Features (105).** Per candidate line: distance to detection (F1), expected token (F2), found token (F3/F4), bracket balance/depth (F5), statement completeness (F6), brace depth and innermost open-block indent (F7), neighbouring-line pattern (F8), indentation deltas, language/category one-hots. Top importances (GB): `is_reported` 0.50, `code_lines_between` 0.19, `F1_dist` 0.11, `global_unmatched_brace` 0.07, `dedent_while_open` 0.04 - i.e. much of the model's skill is learning *when to trust the compiler's line* plus brace/semicolon structure.
**Models.** RandomForest vs GradientBoosting fit on train, selected on validation top-1 (GB 98.7% vs RF 98.0%; rule engine 92.7%). The test split is touched only by the benchmark, once, after selection.
**Metrics.** top-1/top-3/MRR vs the injected line, mean |line error|, Wilson 95% CI, exact sign test on discordant pairs, category accuracy, and *suggestion correctness* (strategy's top-1 line + shared patch templates -> code compiles; first 25 test samples per language).
